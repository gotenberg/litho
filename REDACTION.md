# Redaction (apply) in litho

Plan to permanently remove content from a PDF, not just cover it.

litho can already _detect_ failed redactions: `Reader.ExtractRedactedText` (the `redactions` CLI command) surfaces text that sits under redaction marks but was never removed from the content stream — the single most common real-world PDF data leak. The gap is the cure: litho cannot _apply_ a redaction. This is a security-critical, self-contained capability and the only one in the roadmap whose absence is itself a standing hazard: litho diagnoses a leak it cannot fix.

> **Priority.** Redaction's core (text/image/annotation excision + sanitization + full rewrite) needs **none** of the rendering bundle ([RENDERING.md](RENDERING.md) etc.); only the optional pixel-verify hook and the conservative vector-path fallback do. Together with [ACCESSIBILITY-AUTOTAGGING.md](ACCESSIBILITY-AUTOTAGGING.md) it is the cheap, high-value, rendering-independent, **ship-early** pair. Retiring this hazard does not require committing to the rendering bet.

## What redaction actually is

True redaction is **content removal plus document-wide sanitization**, never a drawn black rectangle. Covering text with a filled rect is the classic, catastrophic failure: the bytes remain and any extractor recovers them. The threat model is strict — an attacker or auditor must not recover excised text or pixels from _any_ residual structure in the output. The reference vector lists are the NSA's "Redacting with Confidence" and the glyph-advance reconstruction attack (arXiv 2206.02285, "Story Beyond the Eye").

### Two distinct jobs, often conflated

1. **Full rewrite** kills incremental-update history and orphaned objects. litho's `WithFullRewrite` already does this — but it deep-copies the entire object graph reachable from `/Root` (`pkg/internal/mutations/rewrite.go`, via `Copier.CopyRef`), so it drops **only unreferenced** objects. It is **necessary but not sufficient.**
2. **Scrubbing catalog-referenced structures** that hold a _second copy_ of the content. Every structure below survives a full rewrite verbatim and must be handled explicitly. This is the job the naive "full rewrite removes the residue" model misses entirely.

### To redact region R on page P

- **Excise marked content (geometry-driven, visibility-independent).** Remove every text-show, image-paint, and path-paint operator whose marks intersect R — **regardless of fill/stroke color, alpha, or text rendering mode.** Invisible text (`Tr 3`, the OCR hidden-text layer), white-on-white overdraw, and content inside an _off_ optional-content group all count: excision keys on geometry through the CTM, never on whether a pixel was visible. Operators straddling R are rewritten (split a `TJ` run at glyph boundaries; clip an image in image space).
- **Avoid the glyph-advance leak.** After splitting a text run, do not leave width-revealing spacing: the residual advances of surviving neighbors encode the removed glyphs' widths and reconstruct the word (arXiv 2206.02285). Collapse the gap to a fixed mark width or re-lay the survivors so residual advances carry no information.
- **Blank underlying image pixels in image space.** Overwrite the covered pixels in the image data (clip is reversible, so never treat clipping as removal); this applies to any image whose sensitive pixels map under R through the CTM, including images clipped to a sliver. Re-encode the image — but see the [JBIG2/JPX limit](#limits-and-honest-scope).
- **Re-subset embedded fonts.** If a glyph/CID now appears only under the mark, its outline still sits in the embedded font, and `/ToUnicode` + a custom `/Encoding /Differences` can themselves spell the redacted characters. Re-subset to drop the outline and prune the matching `ToUnicode`/`Differences`/`CIDToGIDMap` entries (shares the [OPTIMIZATION.md](OPTIMIZATION.md) subsetter).

## Document-wide sanitization — the leak vectors

Each of these is reachable from `/Root` and survives full rewrite. The spec covers them by default (security operations fail closed, so scrubbing is opt-_out_, not opt-in):

| Vector                                                   | Why it leaks                                                                                                                                                             | Action                                                                                                                                                                                                                    |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Structure tree** (`StructTreeRoot`)                    | `/ActualText`, `/Alt`, `/E` expansion, and MCID-linked text hold a parallel copy of the page text — and tagged PDFs are the _common_ case                                | For each excised marked-content sequence, find its MCID in the page `/StructParents`/ParentTree and remove or neutralize the structure element (incl. `/ActualText`/`/Alt`/`/E`); fail closed on an unsplittable straddle |
| **Page `/Thumb`**                                        | A producer-baked raster of the _whole pre-redaction page_; image blanking targets content XObjects, not `/Thumb`                                                         | Drop `/Thumb` (cheap, always safe) or regenerate from the redacted page                                                                                                                                                   |
| **Annotations & form fields (document-wide)**            | `/Contents`, `/RC` rich text, form `/V`/`/DV`, link `/URI`, and `/AP` appearance streams can quote redacted text even _outside_ R                                        | Token-scan all annotation values + `/AP` + AcroForm `/V` document-wide, not just those intersecting R                                                                                                                     |
| **Optional content** (`OCProperties`/OCG)                | A hidden layer (or OCG-gated alternate image) holds content the interpreter may skip                                                                                     | Excise OCG-hidden content geometrically; scrub OCG-gated alternates                                                                                                                                                       |
| **Outlines / Dests / Names**                             | Bookmark titles and named-destination keys routinely quote heading/section text                                                                                          | Token-scan and scrub; fail closed on straddle                                                                                                                                                                             |
| **`/PieceInfo`** (page + document)                       | Producer-private app data (InDesign/Illustrator blobs) can hold the original text                                                                                        | Drop wholesale (private, non-rendered)                                                                                                                                                                                    |
| **Metadata** (Info + XMP, catalog _and_ per-object)      | `/Title`/`/Subject`/`/Keywords`, XMP `dc:*`, and especially XMP history (`xmpMM:History`/`DerivedFrom`) record prior states; XObjects/images carry their own `/Metadata` | Default-scrub the full standard set + XMP history; caller re-adds explicitly                                                                                                                                              |
| **Document JS / actions**                                | `/OpenAction`, document/page `/AA`, and the `Names/JavaScript` tree can read or echo content                                                                             | Strip all (new work — see table below)                                                                                                                                                                                    |
| **Embedded files / legacy search index / `/Collection`** | Attachment bodies, a legacy embedded full-text index, and portable-collection metadata each hold text independently                                                      | Default attachment removal **on**; drop the search index and `/Collection`                                                                                                                                                |
| **Digital signatures / `/DSS`**                          | A signature `/ByteRange` covers original bytes; a prior signed revision is a full pre-redaction copy; `/DSS`/VRI reference prior revisions                               | Drop all `/Sig` fields, `/Perms`, and `/DSS` (full rewrite already invalidates them)                                                                                                                                      |
| **Embedded font programs**                               | See font re-subset above                                                                                                                                                 | Re-subset / prune                                                                                                                                                                                                         |
| **Incremental history + orphans**                        | Prior revisions are full pre-redaction copies                                                                                                                            | `WithFullRewrite` (already handled)                                                                                                                                                                                       |

## Design

- **Region source.** Apply the document's own `/Redact` annotations, or caller-supplied `[]Rect` per page. `Writer.Redact(ctx, regions, opts)`.
- **Excision primitive** in `pkg/internal/mutations` + the writer (geometry-driven, visibility-independent, as above). **This is the shared deliverable** flattening reuses; it lives with redaction so redaction does not inherit the rendering gate.
- **Sanitization pass** over every vector in the table, default-on.
- **Fail-closed is enforceable, not aspirational.** The interpreter classifies every operator/structure touching the redaction set into `{excised, provably-irrelevant, unknown}`; **any `unknown` forces a hard refusal naming the construct.** Refusal beats half-redaction.
- **Verification hook (honestly scoped).** Re-running `ExtractRedactedText` + a pixel check covers _only the page content stream and rendered pixels_ — it does **not** see the structure tree, `/Thumb`, metadata, or annotation values, so it is a check, not a proof. Add a belt-and-suspenders **document-wide token scan**: assert no known-redacted token appears in any decoded string/stream (structure tree, outlines, dests, Info/XMP, annotation values/`/AP`, JS) before writing.

Per CONTRIBUTING: redaction is destructive and security-critical, so it is explicit (never a default), the report enumerates exactly what was removed per region and vector, and clause-grounding cites the NSA guidance and arXiv 2206.02285 at the decision sites.

## Plan

- **PR1 — region API + report shape.** No removal yet. `/RD` is dropped from this PR: the table above
  measures its corpus reach at zero, and `/RD` is not a redaction-annotation entry (ISO 32000-1
  Table 189 lists `/QuadPoints /IC /RO /OverlayText /Repeat /DA`; `/RD` belongs to Square/Circle and
  FreeText). Caller-supplied `[]Rect` per page is the region source with evidence behind it; the
  document's own `/Redact` annotations stay a secondary input.
- **PR1b — make unrecognised constructs reportable.** The prerequisite for fail-closed, and the real
  first code increment: the machine must be able to tell a caller it met an operator it does not
  model (`Do`, `sh`, `gs`, inline images, anything absent from `opHandlers`). Additive and opt-in, so
  existing callers and the corpus gate are unaffected.
- **PR2 — Content-stream excision primitive. Landed** for text and filled paths, as a byte splice
  exactly as prescribed: `ParseStreamDataWithOffsets` returns contiguous, monotonic `[]ByteRange`
  spans parallel to the operations, and `tagging/injectMarks` was the template (cursor-walk, gaps
  copied verbatim, the same span validation and alloc-first `Pending()` read). Selection is geometric
  and visibility-independent, so `Tr 3` invisible text, white-on-white overdraw and OCG-hidden text
  are all removed on geometry alone. The partial-`TJ` glyph-advance case is **refused**, not split:
  splitting a run has to answer the advance leak (arXiv 2206.02285) first, which is PR4 work.
  (Shared with flattening.)
- **PR3 — Image-pixel blanking + re-encode. Landed** for image XObjects litho can
  decode: the covered samples are overwritten, the image object is replaced in place via
  `AllocAt`, and the result is transcoded to 8 bits under `/FlateDecode`, in its own colour
  space where litho reads one, so the missing JPX/DCT encoders never block clearing. Samples are tested by carrying each one
  forward through the CTM, not by clearing an inverse-mapped bounding box, which would
  destroy content outside R under a rotated placement. **In-region annotation removal has landed**:
  an annotation whose normalised `/Rect` sits inside a region is dropped from the page's `/Annots`,
  because clearing the content stream leaves it whole — its `/Contents` and `/A /URI` survive, any
  `/AP` goes on drawing over the cleared area, and its `/Rect` marks exactly where the removed
  content sat. Measured reach: 84,788 annotations across 831 of 5,171 corpus files, 91% of them
  `/Link`. Three refusals rather than approximate removal: one **straddling** the region (an
  annotation is atomic, so dropping it would take link or widget behaviour outside R, which is why
  `ErrPathStraddlesRegion` exists for paths), a **`/Widget` that is a kid of a field above it**
  (detaching one means pruning that parent's `/Kids` and settling what becomes of a field whose kids
  have all gone; clearing the value is `ScrubFormFieldValues`' job). A **parentless** widget is not
  refused: it is the merged field-and-annotation of ISO 32000-1 12.5.6.19, so it is its own root
  field and goes from the page and from AcroForm `/Fields` together. The last refusal is one
  whose `/Rect` cannot be read (unplaceable is un-rule-out-able, the same reasoning as
  `ErrXObjectUnresolved`). A widget carrying `/Parent` is **detached from that field's `/Kids`** in one hop, and a field whose
  last kid goes keeps its name and type while losing the `/Kids` entry — cascading upward would decide
  for the caller that a named field should cease to exist, and `ScrubFormFieldValues` already clears
  the value. One hop also sidesteps `/Parent` cycles, which are real: 16 of them in one corpus file,
  against a deepest genuinely acyclic chain of 7. What still refuses is only the case with nothing to
  rewrite — a `/Parent` written inline, or a widget written directly into `/Annots`.
  **A stencil mask now blanks as a stencil.** It keeps `/ImageMask` at one bit a sample and its
  covered samples are cleared to _unpainted_, because ISO 32000-1, 8.9.6.2 gives a mask no colour of
  its own and paints it with the fill colour in force: transcoding it to DeviceRGB would stop it
  taking that colour, and clearing it to black, which is how a picture is blanked, would add ink
  rather than take the shape away. Measured on `pkg_testdata__Wonderwall.pdf`, whose 2312x3307 mask
  went from a refusal to a redaction whose replacement is still
  `/ImageMask true /BitsPerComponent 1` with no `/ColorSpace`. Still open here:
  inline images (their
  samples sit in the content stream, so blanking means splicing bytes rather than replacing an
  object), translating `/Decode` for the indexed images
  that still refuse, and a stencil carrying `/SMask`, which is refused because no clause of
  ISO 32000-1 gives a soft mask a meaning on a mask, so dropping it and carrying it over are both
  guesses.
- **PR4 — Document-wide sanitization** (the full vector table) + font re-subset + full-rewrite
  enforcement + the token-scan verification gate; fail closed. **Both halves have landed.** `mutations.SanitizeDocument`
  is the gate itself: it runs the document-wide passes over a redaction's `RemovedText`, then
  verifies with `ScanOutputForTokens` and **fails closed** when a copy survives. Its two failure
  modes differ on purpose — a pass that _refuses_ rolls everything back (a half-scrubbed document is
  worse than an unscrubbed one), while _verification_ finding a survivor leaves the correct edits
  queued and names the objects in `SanitizeReport.Scan`, because the usual cause is a home no
  token-driven pass reaches, such as `/Info`, which `ClearMetadata` owns. The scan half:
  `mutations.ScanForTokens` walks every object in the file — not the places a redaction
  happens to know about, which is the point, since it catches the vector nobody enumerated. Strings
  are compared after `DecodePdfString`, so a UTF-16 copy matches like a PDFDocEncoding one, and stream
  data is compared **decoded**, so a word inside a Flate-compressed structure tree or appearance
  stream is not missed. It returns the objects it could **not** read alongside the hits: a scan that
  skipped a stream has not proved that stream clean, and reporting the empty hit list as success would
  be the same false negative the scan exists to prevent. **Removal now reports what it cleared** and feeds it:
  `RedactPageRegions` returns a `RedactReport` whose `RemovedText` holds one string per removed
  show-text operator — the run it drew, not its glyphs, because one extracted element is a single
  glyph and handing single letters to a scan matches nearly every object in a real file. Runs that
  decode to nothing are dropped, for the same reason an empty token is refused. **The scan now answers
  for the output, not only for the input.** `ScanForTokens` reads the document as parsed, which is the
  honest question for the bytes on disk and for an incremental update, since that appends and leaves
  every superseded object in the file. `ScanOutputForTokens` asks instead what a full rewrite would
  write: it resolves every reference through the allocator first, so it reads the replacement a
  redaction queued rather than the original, and it reaches outward from the roots `FullRewrite`
  copies (the catalog, and the trailer `/Info`, which nothing in the catalog graph reaches) rather
  than sweeping the object table. Reaching outward is what drops the page's original content stream
  from the answer: an excision leaves it referenced by nothing, and a full rewrite never copies it, so
  reporting it would name a leak the output does not have. The two are not interchangeable, and which
  one is honest depends on how the caller writes the file. **The structure tree is now scrubbed**, which is the
  first vector past the page itself and the one that matters most, since a tagged PDF keeps a parallel
  copy of its text in `/ActualText`, `/Alt` and `/E` and tagged PDFs are the common case. The page's
  `/StructParents` keys the `/ParentTree` entry, which for a page is an array indexed by MCID
  (ISO 32000-1, 14.7.4.4), so a removed MCID reaches the element describing it; the element keeps its
  `/S` and loses only the text-bearing entries. Two cases refuse instead: an element describing both
  removed and surviving content (one MCID spanning operators on both sides, or two MCIDs naming the
  same element — a single element commonly spans a whole paragraph, so this is ordinary rather than a
  corner case), and an element written directly into the array with no object number to replace.
  **The redacted page's `/Thumb` and page-level `/PieceInfo` are now dropped** once something was
  actually removed, and only then: a page that cleared nothing keeps its thumbnail. `/Thumb` is a
  producer-baked raster of the page as it was, so image blanking — which rewrites content XObjects —
  never reaches it and the removed words stay visible in it. The **catalog's** `/PieceInfo` is
  deliberately left alone: ISO 19005-4, 6.1.3 forbids `/Info` in the trailer unless the catalog
  carries `/PieceInfo` (a rule litho both checks and repairs), so dropping it would make a conforming
  PDF/A-4 file non-conforming whenever `/Info` stayed. Clearing that one means clearing `/Info` with
  it, which is a document-wide decision rather than a page-scoped edit's to make. **Annotation text is now scrubbed document-wide** by
  `mutations.ScrubAnnotationText`, which takes the removed tokens and clears `/Contents`, `/RC` and
  `/URI` on any annotation quoting one — document-wide rather than in-region because an annotation on
  page five can quote text redacted on page one, and a link target routinely spells the heading it
  points at. Two refusals: an annotation whose `/AP` still paints text (the words are drawn by the
  appearance's own content stream, so clearing `/Contents` would leave them on screen, and only a
  widget's appearance regenerates from its field value), and one written directly into `/Annots` with
  no object number to replace. **Form field values are deliberately not covered**: `/FT` and `/V` are
  inheritable (ISO 32000-1, 12.7.3.1), so a value can live on an ancestor field dictionary appearing
  in no page's `/Annots`, and walking annotations would silently miss it — that needs an ancestor walk
  of its own. The pass is **not wired into `RedactPageRegions`**: it is document-wide while that
  function is page-scoped, so a caller runs it with `RedactReport.RemovedText` — and
  `mutations.SanitizeDocument` is now that caller, running all three document-wide passes in turn and
  then failing closed on whatever survives. Its in-region
  counterpart is a separate pass and that one **is** wired in: `RedactPageRegions` drops annotations
  whose `/Rect` sits inside a region (see PR3 above). The two are complementary rather than
  alternatives — one selects an annotation by what it says, the other by where it sits, and an
  annotation can leak either way. **Form field values are now scrubbed too**, by
  `mutations.ScrubFormFieldValues`, which closes the half the annotation pass deliberately left open.
  `/V` and `/DV` are cleared on the dictionary that actually **states** them, which is frequently an
  ancestor field appearing in no page's `/Annots` at all, because both entries are inheritable
  (ISO 32000-1, 12.7.3.1) — clearing only what the widget carries looks complete and leaves the value
  sitting in the parent. The widget's `/AP` goes with it: the appearance draws the old value, and
  unlike a markup annotation a widget's appearance is one litho regenerates from the field value, so
  dropping it is recoverable rather than destructive. It refuses when the dictionary stating the value
  is written directly into its child, having no object number to replace. **Outline titles are now scrubbed too**, by
  `mutations.ScrubOutlineTitles`, which walks the tree from the catalog's `/Outlines` rather than page
  by page: a bookmark title routinely repeats the heading it points at, so a cleared page can still
  spell it in the outline panel of every viewer that opens the file. The title is **emptied, not
  deleted** — `/Title` is required on an outline item (ISO 32000-1, Table 153), so removing the entry
  would leave an item the spec disallows; the bookmark survives, points where it did, and says
  nothing. An item written directly into its parent's `/First` or a sibling's `/Next` **refuses**
  rather than being walked past: it cannot be rewritten, and because `/Next` lives inside it every
  later sibling is reachable only through it, so continuing would report a clean outline while the
  titles behind it still quote the removed text. Font re-subset splits in two, and only the first half is
  done. **Detection landed**: `RedactReport.FontsFullyRemovedOnPage` names the fonts whose every
  glyph on the redacted page was removed, so a caller is told which embedded programs now carry
  outlines describing nothing the page still draws. It is **page-scoped** — the font may be used on
  another page, and its program holds the outlines either way — and it **reports rather than
  refuses**, because a heading set in its own font and redacted whole is the ordinary case, so
  refusing there would block redaction on everyday documents. **Re-subsetting is still untouched**:
  the only subsetter (`mutations/stamp_font_subset.go`) is TrueType-only and serves the stamping path,
  where litho generated the font and already knows every glyph it used; redaction is the inverse
  problem across three embedded formats (`FontFile`, `FontFile2`, `FontFile3`), and the glyph-level
  usage mapping it would need does not exist. Metadata needs no new scrubber — `mutations.ClearMetadata` already empties
  the `/Info` dictionary and drops the catalog's `/Metadata` XMP stream, which is the whole of that
  row; what is missing is composing it into a redaction flow rather than any new code. Until the
  remaining vectors are cleaned and composed, the scan continues to tell you the document is dirty
  without cleaning it.
- **PR5 — public surface + CLI. Landed for the region source, not for `--apply-marks`.**
  `Writer.Redact(ctx, regions)` runs eagerly rather than queueing, because a caller has to
  learn whether the document may be written at all before writing it, and it forces a full
  rewrite because the verification scan answers for the file a full rewrite would produce —
  an incremental update would append the edits and leave every superseded object, the
  original content stream among them, in the file. It composes what PR4 left uncomposed:
  `RedactPageRegions` per page, then `ClearMetadata` (the `/Info` copy no token-driven pass
  reaches), then `SanitizeDocument`. Both failures are public and both leave the `Writer`
  untouched: `ErrRedactionRefused` when content cannot be removed exactly, and
  `ErrRedactionIncomplete` when verification still finds a copy, with
  `RedactReport.SurvivingCopies` naming where. The composition is pinned by a test that
  fails when `ClearMetadata` is removed, so it cannot rot into a no-op.
  `litho redact --region page:x,y,width,height` (repeatable) reports per vector in text or
  JSON, and creates the output file only after the redaction succeeds, so a refusal leaves
  nothing on disk. Note the flag takes width and height while `RedactRegion.Rect` is
  `[llx, lly, urx, ury]`; the conversion is explicit in `parseRedactRegion`.
  **`--apply-marks` is NOT built**: the table above measures the document's own `/Redact`
  annotations at 4 files in 5171, none carrying `/QuadPoints`, so the caller-supplied
  region is the source with evidence behind it.

## Limits and honest scope

- **JBIG2 and JPX images cannot be re-encoded in their own filter** — litho decodes both but encodes neither. Blanking answers this by **transcoding**: a cleared image is rewritten at 8 bits under `/FlateDecode` whatever it arrived as, in its own colour space where that is a device, ICC-based or CIE-based one and in DeviceRGB otherwise, so the absence of a JPX or DCT encoder never blocks clearing an image litho could decode. Three cases still **refuse** rather than leave pixels in place. A filter litho cannot decode at all (an unknown one) reports `ErrImageNotDecodable`, because an image it cannot read is one it cannot prove it cleared. An **indexed** image whose colour table cannot be read reports the same sentinel: per ISO 32000-1, 8.6.6.3 its samples are one index per pixel whatever the base space is, so reading them in that base can never be right, and a base litho assigns no component count used to collapse to DeviceRGB and report complete data as "too short for RGB image". `/Lab` was that base on every instance found (4 images across 2 pdfjs documents; no other corpus holds one) and now **decodes** instead: its entries are scaled onto `/Range`, converted to XYZ by the g() of ISO 32000-1, 8.6.5.4 against the declared `/WhitePoint`, and matrixed to sRGB with no chromatic adaptation, matching PDF.js for the same construct. A `/Lab` base missing the `/WhitePoint` Table 65 requires still refuses rather than rendering against a guessed illuminant, as does any other base with no known component count. **Sub-8-bpc samples now unpack** (`unpackSamples`, per ISO 32000-1 8.9.3: MSB-first, each row padded to a byte boundary), so 1, 2, 4 and 16-bit images decode instead of being refused outright. Measured over the corpus, this was never really a JBIG2 question: of 10,534 sub-8-bpc images the largest cells are bilevel and already decodable — **7,936 CCITTFax, 1,809 Flate and 124 unfiltered, each of those counts at 1 bpc** — against only **298 JBIG2 (2.8%)**, which litho now decodes natively. Framing the gap as "JBIG2" understated it by roughly thirty-fold. `/Decode` used to gate the remainder: **5,386 of the 10,534 (51%) carry `/Decode` or `/Mask`**, against 1.3% of 8-bpc images, because an inverted `/Decode [1 0]` is routine on bilevel scans. **That refusal is now narrowed to the cases that actually need it.** `blankImage` writes a fresh dictionary carrying no `/Decode`, so wherever `DecodeImage` already folded the array into the pixels the entry is redundant and the image is blanked rather than refused. It still refuses where the decode did **not** apply it, which `pdfimage.AppliesDecodeArray` decides — now only an **indexed** image whose colour table cannot be read, which the decoder refuses anyway. An indexed image's array remaps palette indices, and the decoder now maps the indices through it before the lookup, so an indexed `/Decode` is folded into the pixels like any other. **A JPEG was excluded too until `DecodeImage` stopped double-decoding.** It had a branch of its own that handed the stream to `image/jpeg`, on the premise that the filter pipeline passed `DCTDecode` through untouched; it does not (`filter.Decodable` lists it, and `decodeDCT` returns decoded samples), so `image/jpeg` was re-decoding already-decoded bytes and **no JPEG decoded at all** — breaking OCR on JPEG-scanned pages and blanking of JPEG images alike. A JPEG now takes the ordinary sample path, so its `/Decode` is applied and the entry is redundant on re-encode. Its sample shape is **measured** from the decoded length rather than taken from `/ColorSpace`, because `decodeDCT` reports whatever the codestream's colour transform yielded: a grayscale JPEG declared `/DeviceRGB` is the common disagreement, and believing the declaration asks for three bytes a pixel when one arrived. `/Mask` and `/ColorKeyMask` always refuse: they say which samples are painted at all, not how a sample's value is read. litho never silently leaves such an image untouched. (Same caveat in [OPTIMIZATION.md](OPTIMIZATION.md).)
- **Vector path excision is harder than text/image.** A path wholly inside R is removed as a whole run, from its first construction operator through the paint operator that ended it: dropping the paint operator alone would leave the construction operators to merge into the next path, so removing a path would draw one. Three cases are refused rather than removed, because removing them would change the page outside R: a path **straddling** R (it would lose ink the caller never selected — geometric clipping and re-emission would lift this), a **stroked** path (the stroke spreads half a line width past the geometry the machine records, so containment is unprovable from the bounds — inflating by the line width in force would lift this), and a path a **W/W\*** took part in (it also narrows the clip for later content). The conservative fallback rasterizes the affected region (needs [RENDERING.md](RENDERING.md)) rather than leak. The token scan + pixel-verify catch misses.
- **"Redaction-grade" is a claim, not a default.** Fully remove (and prove it) or refuse — partial redaction is worse than none. No "black box only" mode.

## Out of scope

- Automatic PII detection (deciding _what_ to redact) — caller policy, possibly via the OCR hand-off.
- Reversible/encrypted redaction.
