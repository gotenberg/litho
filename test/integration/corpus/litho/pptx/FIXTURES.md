# litho/pptx corpus fixtures

Self-authored PresentationML presentations that cover what Microsoft PowerPoint prints. Each fixture is an unpacked OOXML part tree under `parts/<name>/`, hand-written ECMA-376 Transitional XML as PowerPoint 2016+ writes it: real content and relationship types, `mc:Ignorable` extensions (`p14`, `a14`, `a16`), and `mc:AlternateContent` with the fallback PowerPoint writes for newer constructs. `go run ./test/integration/cmd/corpus build --corpus=litho/pptx` zips each tree deterministically into the testdata. An `options.json` beside the parts holds the Gotenberg route options the fixture converts with (notes pages, hidden slides, page selection).

The references are Microsoft's: Office for the web prints each document through Microsoft Graph (`make corpus-references CORPUS=litho/pptx` with `LITHO_CORPUS_MSGRAPH_TOKEN`, see `cmd/corpus/msgraph.go`), and each reference records the day it was built, since the service has no version to pin. Graph applies no conversion options, so the fixtures with an `options.json` (8: `deck-conference-talk`, `deck-training`, `hidden-slides-exported`, `notes-pages`, `page-selection`, `handouts-2`, `handouts-3`, `handouts-6`) have no reference of their own: the three whose `options.json` names `reference_of` borrow the reference of the fixture it names, a deck whose slides are the handout pages litho lays out, and the `diff` feature leaves the other five unscored; the `robustness` feature and the other cells still read them. Every other fixture converts: Office refusing one means the part tree is not valid OOXML, and the tree is fixed, not the reference skipped. Hostile documents are generated in Go from `minimal` and are listed in their own section.

Fonts are Calibri, Calibri Light, Cambria, Arial, Times New Roman and Courier New, which have metric-compatible free substitutes, plus DejaVu Sans, Noto Sans CJK, Noto Sans Thai and Noto Sans Devanagari for other scripts. A few runs name a missing font (Aptos, Segoe UI Emoji, MS Mincho, a made-up name) to exercise fallback. Every part passes `xmllint`, and every fixture passes an ECMA-376 schema validation.

`corpus build` generates, beside the hostile documents, one deck per slide size from the committed `paper-deck` (`paperDocs` in `cmd/corpus/papers.go`), never committed. `paper-deck` is two 4:3 slides (`sldSz` `screen4x3`, 10 by 7.5 inches) on the master of `size-4x3`; each generated deck changes `sldSz` alone, so the master's placeholders keep their place and the size decides only the page box and what the slide clips. No deck takes an option: no engine re-papers a deck.

## Not authored or simplified

- Embedded fonts (`p:embeddedFontLst`): PowerPoint stores them as obfuscated `.fntdata` subsets, which cannot be produced faithfully by hand.
- Embedded video and audio: no encoder is available to make a small valid MP4 or MP3, so media is linked (`r:link`, external) and prints its poster frame.
- Embedded workbooks for charts (`c:externalData`): charts carry cached values only, which is what prints. The OLE fixture embeds a small workbook package.
- Regional map charts (`cx` `regionMap`): PowerPoint fetches the geography from a web service.
- 3-D models (`am3d`) and Cameo or live camera objects: they need binary glTF parts and PowerPoint 365 features.
- Legacy VML parts (`vmlDrawing`) for OLE previews: the fixtures use the PowerPoint 2010+ `p:pic` preview inside `p:oleObj`.
- SmartArt layout definitions are compact versions of the built-in ones with the real `uniqueId`; the `dsp` drawing cache holds the shapes that print.
