# litho/ods corpus fixtures

OpenDocument spreadsheets that lock how a conversion applies the paper and the orientation to the sheets of a workbook, scored by the `diff` feature (see `FEATURES.md`) against LibreOffice Calc. No corpus of LibreOffice's test documents carries the route's options.

Each source is a directory, `sources/<name>/`, holding one flat OpenDocument file, plain XML that lives in git, and optionally `options.json`, the LibreOffice route's form fields it converts with (`fixture.LoadOffice` reads them as for the other Office corpora: `paperWidth` and `paperHeight` in inches, `landscape`, `nativePages`, `nativeBookmarks`, `exportNotesPages`). A source that differs from another by its options alone links that source's document. The references are LibreOffice's, built by `corpus references` with the image `GOTENBERG_IMAGE` in `corpus/versions.env` pins (`gotenberg/gotenberg:9.4.1`, LibreOffice 26.8.2.2) through `/forms/libreoffice/convert`, into the testdata, never committed. The documents draw Liberation Serif and Liberation Sans, which the image and the fixture fonts both carry, and were written by a script for this corpus; the sheet selection documents are LibreOffice's flat saves of `litho/xlsx`'s `sheet_selection` and its twins, in Calibri, which Carlito stands in for. The options `sheets`, `sheetNumbers` and `hiddenSheets` are litho's own: no route takes them, so their sources borrow, by `reference_of`, the reference of a document that holds exactly the sheets they print.

The pinned image leaves LibreOffice's locale empty, so LibreOffice prints a page that names no size on A4 (`no-page-size`: 595.3 by 841.9 points), litho's default too: the `diff` feature converts these sources with no default paper.

## Writing systems

The spreadsheets below each lock how Calc prints one script in cells. Their running text is the Universal Declaration of Human Rights in each language, the United Nations' translations as the UDHR in Unicode project transcribes them (`efele.net/udhr`, `github.com/eric-muller/udhr`); the strings that show a rule come from the standard that states it, cited in the document. Each document names its faces in its styles, faces of the Gotenberg image that the fixture fonts carry: Liberation Sans for Latin, Noto Sans CJK JP, SC, TC and KR as the Asian font, and DejaVu Sans (Arabic, Hebrew), Noto Sans Devanagari or Noto Sans Thai as the complex font, each with its `style:language-*` and `style:country-*`. The faces in the table are those `pdffonts` reads in each reference. Asian text stays at the regular weight: the fixture fonts hold no bold Noto Sans CJK, which the image has.

| ------------------ | ------------------- | ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `rtl-sheet`        | 3                   | DejaVu Sans, Liberation Sans                          | A Hebrew and an Arabic sheet whose table style sets `style:writing-mode="rl-tb"`, so column A is the rightmost: header cells, numbers, years, percentages, a word in Latin and article 1 wrapped in three merged cells; then a left-to-right English sheet |
| `cjk-cells`        | 1                   | Noto Sans CJK JP, SC and KR, Liberation Sans          | Article 1 in Japanese, Simplified Chinese and Korean, wrapped in cells (`fo:wrap-option="wrap"`), beside the same title stacked (`style:direction="ttb"`) and turned a quarter (`style:rotation-angle="90"`), in three rows 45 mm high                     |

## Expected text

Two spreadsheets print text LibreOffice writes in a form PDF.js reads apart from the page. Each names `expectedText` in its `options.json`, beside a file `expected-text.txt` holding the page's text in reading order, written from the source's runs: what the pages print, generated list numbers and bullets included, the characters as the source holds them. A line ends where the reference's page ends it inside Thai or CJK text, which no space parts, so that a reader's tokens are the file's (`FEATURES.md`, "Expected text"). The `diff` cell scores litho's text against the file and reads the reference for the pages, layout, links and outline alone; neither the key nor the file changes the reference. What the reference holds, as PDF.js reads it, and what the file adds:

| Source             | What PDF.js reads of the reference                                                                                      | The file                                                                                                                               |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `indic-thai-cells` | Devanagari and Thai marks as items of their own or mapped to other characters                                           | The cells row by row, each Thai line ended where its cell wraps it                                                                     |
| `rtl-sheet`        | The cells of each right-to-left row run together (`סעיףנושאשנהאחוז`); the Arabic sheet in visual order with stray marks | The cells row by row, sheet by sheet; `0.125` in the `0%` format as the page prints it, `13%`, where the cell's cached text says `12%` |

## Paper documents

`corpus build` generates the paper documents from the committed `paper-grid` and `paper-fit` into the testdata (`paperDocs` in `cmd/corpus/papers.go`, `papers/<name>/`), never committed. They are the workbooks of `litho/xlsx`'s bases in ODF: a grid of 20 columns by 130 rows with a header and a footer, and 16 columns by 120 rows fitted to one page wide (`style:scale-to-X` 1, `style:scale-to-Y` 0), on portrait Letter. The LibreOffice route takes the paper options, so the option documents have references of their own. Measured on the references: LibreOffice prints each option workbook as it prints the workbook stating that paper itself, the same pages and the same text (`paper-grid-option-a5-portrait`: 20 pages, as `paper-grid-a5-portrait`).

| Fixture                                          | Count | Page setup                                                                                                 |
| ------------------------------------------------ | ----- | ---------------------------------------------------------------------------------------------------------- |
| `paper-grid`, `paper-fit`                        | 2     | Committed, portrait Letter                                                                                 |
| `paper-grid-<paper>-<orientation>`               | 16    | The page layout on A3, A4, A5 and B5 (ISO 216), Letter, Legal, Tabloid and Executive, in both orientations |
| `paper-fit-<paper>-<orientation>`                | 6     | The fitted sheet on A5, A4 and A3, in both orientations                                                    |
| `paper-grid-default-<orientation>`               | 2     | The page layout without a size, portrait or landscape: LibreOffice's default paper, A4                     |
| `paper-grid-option-<paper>-<orientation>`        | 16    | `paper-grid` with each of the eight papers as options, and `landscape` for the landscape ones              |
| `paper-fit-option-<paper>-<orientation>`         | 6     | `paper-fit` with A5, A4 or A3 as options                                                                   |
| `paper-grid-margins-<set>-<paper>-<orientation>` | 18    | `paper-grid` on A5, A4 or A3 in both orientations, with the `fo:margin-*` of a margin set                  |

`paper-fit` keeps to A5, A4 and A3: its fitting is a scale the paper's width decides, which the smallest, the default and the largest paper bound. The margin sets are those of `litho/odt`, on the same papers.

## Accepted disagreements

- `sheet-selection`: `Summary` links to a cell of `Data`, a hidden sheet. LibreOffice writes that link as a URI of the upload itself, which the cell reads as a link to the first page (`FEATURES.md`, "Links to the upload"); litho drops a link to a sheet that does not print. Link recall is 2 of 3. `hidden-sheets`, where `Data` prints, scores the link.
